# 環境與檔案位置：holo-maker（範例設定）

> 這是**一位使用者**的設定範例，換人時整份改寫。**這裡和任何上傳檔都不能寫金鑰、登入檔內容、Cookie。**
> 使用者曾把金鑰貼在對話裡，已建議他更換；接手時若不確定是否已換，提醒他一次。

## 期限（每次接手都要重新確認）

- Tripo Studio 登入檔與訂閱都有到期日；登入通常比訂閱早到期。舊紀錄寫過登入 2026-10-24、訂閱 2026-10-28，**不確定是否準確**，接手時用工具檢查登入狀態並問使用者。
- 到期前主動提醒使用者重新登入／續訂。

## 圖轉 3D：Tripo Studio（透過 auto-tripo）

- 使用者自己寫的工具 **auto-tripo** 操作 Tripo Studio 網頁版（不是官方 API）。工具本身不在這個 repo；安裝來源與用法向使用者索取。
- **登入**：雲端容器不能自己登入（Studio 網站會擋雲端）。使用者在自己電腦用瀏覽器登入後，匯出瀏覽器登入檔（Cookie／session）交給 Claude。
  - 登入檔**等同帳號密碼**：放在任何 repo 以外（例如 `~/.secrets/`，權限 600），不上傳、不寫進文件或 manifest；**工作結束就刪除**。
  - 開工前先用工具確認登入沒過期；過期就請使用者重新匯出。
- **服務條款疑慮**：用瀏覽器登入檔讓雲端機器操作 Studio，可能不符合 Tripo 的服務條款。使用者知情並自己決定；若要長期無人看管，改用官方 API（需另外申請金鑰、另外買點數，目前沒用）。
- 計價（Premium 訂閱時觀察到）：Direct Texture ×4 一張約 50 點；多視角生成同價；Studio 內建生圖很便宜。
- 速度：一張約 20 分鐘（每個候選 3.5–6.5 分鐘）；伺服器可同時跑多個工作。
- 多視角（正面＋背面）生成：auto-tripo CLI 沒有現成指令，要直接呼叫 Studio 的對應網路端點；端點名稱看 auto-tripo 原始碼或瀏覽器的網路請求，找到後記在工作資料夾的程式裡（不要寫進這個 repo）。
- **Tripo 帳號就是原始模型的永久保存處**（使用者確認）：憑任務 ID 可重新下載，所以 manifest 一定要記任務 ID。

## 圖像生成／編輯

- **一律用 Tripo Studio 的圖片生成**（透過 auto-tripo 的 image CLI，可帶多張參考圖），使用者 2026-10-18 決定。前 1000 次生成免費；Studio 上有 gpt-image 2 可選（也有 nano-banana）。開工前先用 CLI 列出可用模型確認。
- 用途：概念圖、去配件正面圖、配件（尾巴）圖、雙參考重畫背面、上下半身零件圖。
- 舊做法（10/15–10/18 用過）：OpenAI 相容的圖像 API（雲端代理帶認證）。之後不再用。
- manifest 要記每次生圖的任務 ID 與使用的模型。

## 雲端容器

- 會重開或閒置後被回收：背景程序中斷，本機檔案不保證保存。
- 硬碟可用空間小（曾約 40 GB，也見過只剩十幾 GB）；開工先 `df -h` 看；剩不到 3 GB 前就整批封存到 R2。
- 工作資料夾：**不要用這個 skill repo**（使用者要求）。在容器裡另開資料夾（例如 `~/figure-work/`）；容器重開後通常不在了，從 R2／B2／Tripo 取回需要的檔案。
- Blender 可用無頭模式（建 .blend、評估修改器、算圖預覽）。精確布林與修補：manifold3d、trimesh。

4. 讀 `history.md` 的目前狀態，向使用者確認下一步。
5. 建工作資料夾，只取回這次任務需要的檔案，然後依 `references/coordinator.md` 派 agent。
