# 踩過的坑與修正

依主題整理。每條：現象 → 原因 → 修法。

## 溝通與執行

- **把「figure」誤會成簡報圖表** → 使用者講的是模型手辦。不確定的詞先看過去的對話紀錄再回答。
- **實作偷換做法**：描述給使用者聽的方法是對的，但 agent 寫的程式用了捷徑（例如照高度或顏色整片刪面），結果破洞一堆。→ 每次都要求 agent 用截圖驗證「是否真的照描述做」，查錯時派新的 agent 讀程式找出跟描述的差異。
- **誤解使用者的方法**：B2 一開始被做成遮罩剪貼，其實使用者要的是「兩張參考圖重畫」。→ 收到新方法時先用白話覆述確認。
- **叫使用者挑不必要的東西**：使用者已經說全部重做，還做挑圖頁。→ 已表態的事直接做。
- **頁面選項爆炸**：每個實驗都加一個分頁，使用者不知道看哪個。→ 每張只放最新成品，舊版收起來。
- **擅自送出生成**：使用者還沒挑圖就開始生成。→ 先挑後做；若已送出，盡快取消並如實告知。

## 背面頭髮

- 只給正面圖 → 背面頭髮糊成一團。→ 一定要提供背面圖（新 B2）。
- 舊 B2（剪頭髮貼到背面截圖上）→ 邊緣對不齊，還會蓋掉蝴蝶結等配件。→ 改成兩張參考圖重畫。
- 新 B2 的優點：保留側邊髮飾、辮子、蝴蝶結，頭髮流向乾淨。缺點：要先有基準模型。

## 尾巴

- 尾巴跟身體一起生成 → 質感像火龍果。→ 尾巴另外生成。
- 尾巴圖是攤開的大扇形 → Tripo 做成扁平寬毛束，像羽毛或葉子。→ 用細長彎月形的尾巴圖，拿成功的尾巴當範本改形狀。
- 尾巴圖顏色太淡、根部有膚色接頭。→ 顏色照概念圖，提示詞明確要求沒有接頭。
- 尾巴接到屁股側邊、橫著伸出去、掛在大腿前面 → 舊程式假設某個固定方向是背面，身體轉了角度就錯（實例：轉了 34°、43°、61°）；又照抄基準模型自己長歪的尾巴。→ 用骨盆對稱 + 頭髮位置找背面，根部固定在腰後正中間，方向對照概念圖。
- 尾巴浮在身體外、接口露出凸塊 → 切掉根部凸塊、埋進身體、用尾巴自己的毛蓋住接口。

## 上下半身接合

- 「切割縫合」：縫合那一圈皺巴巴、有小破洞。→ 放棄。
- 「只重建接縫那一圈」：殼沒封口，變成蕾絲狀鏤空。→ 放棄（要整個部件先補實）。
- 疊層第一版：腰部一圈透空黑帶、褲子破圓洞、手套繩斷掉、頭髮碎片飄著、尾巴根從破洞露出來 → 程式兩邊各切一刀沒有重疊，又用「靠近頭髮就刪」「顏色像就刪」，還把上半身的手套當成多出來的腿刪掉。→ 改成：只切上半身下襬以下的腿，下半身保持完整只修上緣，垂掛物一律保留。
- 接縫切在大腿上 → 切腿的刀在下襬下面，上半身自己的大腿露出一截。→ 刀要切在下襬裡面。
- 百褶裙從底部看像破洞 → 其實是下半身多長的外套／裙子／包包複本從裙子戳出來，加上裙內黑色空隙。→ 刪掉戳出來的複本，裙內加暗色內襯。
- 雪衣腰部錯位 → 下半身只對齊完整模型，跟上半身差 0.5–1% 高度和 2–4°。→ 在腰部重疊區域彼此精對齊，並修整褲頭貼合外套。
- 疊層之後仍是分開的網格 → 要再做一體成形（見 pipeline.md 第 5 節）。

## 基礎設施

- 從 B2 一次下載 1.1 GB 的舊備份 → 吃光當日下載額度，所有頁面都卡住。→ 下載前先估量；大檔放 R2（下載不收費、沒有每日上限）。
- 雲端機器硬碟塞滿（每個 Tripo 候選約 19 MB、每個封閉模型約 70–85 MB）。→ 每個部位只留第 1 個候選在本機，其他留在 Tripo 帳號；用完的暫存檔立刻刪；送件前檢查剩餘空間。
- 雲端機器會重開／被回收 → 背景程序被中斷。→ 檔案多半還在，叫原本的 agent 從中斷處繼續；重要的對照清單和程式要隨時備份到雲端。
- Artifact 更新時不小心開出新連結 → 更新一定要用同一個原始檔路徑。
