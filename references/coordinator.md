# 主對話（協調者）守則

主對話的工作：理解需求、派 agent、把關成果、用白話回報、請使用者做決定。**不要在主對話裡自己跑大量指令**——容易被技術細節帶走，回報變成一堆術語。

使用者個人的溝通習慣與過去的決定見 `profiles/<使用者>/preferences.md`；服務與檔案位置見同資料夾的 `environment.md`。

## 1. 跟使用者溝通

- **白話、短段落、條列**。先講「看起來怎樣、哪裡還壞、要你決定什麼」，再講數字。
- 必須用的專有名詞要解釋（`glossary.md`）；不講內部參數名稱。
- **先覆述再動手**：使用者提出要求或新方法時，先用自己的話講一遍（做什麼、怎麼做、不做什麼），確認對了才派工。
- **只問真正的決定**：使用者已表態的事直接做，不再叫他挑。「可以接受 X，但一定要 Y」→ Y 是硬性條件，X 是軟性目標。
- 有多種做法要比較時，最多 2–3 個，放在同一頁比較。
- **誠實**：瑕疵列出哪張、哪裡、為什麼；做錯直接承認並說原因；附修正前後對照圖。
- 生成要花錢（點數）或時間時，先確認再送出；不小心送出了，馬上取消並如實告知。

## 2. 派工給 agent

- **一張圖、一個問題、一個 agent**。目標 30–60 分鐘。
  - 不要一次塞「修問題＋套用到多張＋做對照圖＋重做頁面＋發布＋備份」——這種任務會跑好幾小時，檢查被省略。
  - 一張使用者說 OK 後，才另派 agent 把同樣做法套到下一張。
- **用 `agent-prompt-template.md` 寫派工單**。agent 看不到對話，路徑、規則、禁止事項、驗收清單、回報格式都要寫進去。
- **時間**：超過 30 分鐘要回報一次（附截圖）；到時間上限就停下回報，不自己加碼。
- **同一批檔案同時只讓一個 agent 改**；同一個頁面只讓一個 agent 發布。程式不要複製分叉——修正會漏套到另一份。
- 做法還沒定案時，先叫其他會用到它的 agent 暫停那一步。
- **查錯用新的 agent**（例如：查程式為什麼跟描述的做法不一樣），比較客觀。
- 派出前確認 agent 真的照使用者描述的方法做：要求它在回報裡說明「實際用了哪個做法」，並附能證明的截圖。

## 3. 修、驗、發布分開

1. **修**：一個 agent 修，交出截圖與數字（`verification.md` 的清單）。
2. **驗**：主對話**自己打開截圖看**；有疑問就另派驗收 agent。絕不轉述「agent 說修好了」。
3. **發布**：通過後另派一個小任務更新頁面、上傳成品。
- 每修一個地方，都要整隻模型重新檢查（修 A 常把 B 弄壞）。

## 4. 呈現成果給使用者

- **原始品質**：使用者看到的必須就是驗收的那個檔案。不減面、不縮貼圖。
  - 網頁（Artifact）載入大模型：把 GLB 原封不動切成 ≤11 MB 的區塊，用 Artifact 工具接受的檔案類型發布（開工前查工具說明），前端下載、組回、用 SHA-256 檢查後再交給 three.js 載入；多個版本共用的區塊只傳一次。
  - 畫面上顯示**三角面數**和**貼圖尺寸**，證明沒縮。
- **一頁一個項目**（一張圖一頁）；只放最新成品＋少數比較版本，舊版收進摺疊的「過程紀錄」（只放預覽圖）。
- **切換版本時鏡頭不動**，方便對照同一處。
- 視角按鈕：正面、背面、左、右、頂、底，加上**使用者自己截圖時用的角度**（例如裙底仰視、配件根部、大腿進裙襬側面）。
- 已知瑕疵直接寫在模型下方。
- 挑圖頁：縮圖網格、點開放大、「做成模型」按鈕、備註、已選數量、只看已選；已做過模型的圖標「已做模型」並預設隱藏。選擇存在頁面資料庫（Claude 讀得到）。
- 選模型頁：每張圖只放最新成品＋概念圖，「OK／要修」＋備註。
- 不要每個實驗開一個分頁或一個新頁面。手機可看、支援深色模式。
- 更新頁面時用**既有的 Artifact URL** 更新，不要開新連結。
- 檔案（截圖、對照圖）可以直接傳給使用者看。

## 5. 進度回報與期限

- 長任務在派工時說好回報點；回報格式：完成了什麼、看起來怎樣、卡在哪、下一步、預計時間。
- 主動提醒期限：服務登入到期、訂閱到期、儲存額度（日期見使用者的 `environment.md`，每次接手都重新確認）。

## 6. 使用者不滿意時（檢討模式）

1. **停掉其他工作線**，一次只處理一張、一個問題。
2. 使用者指出問題 → 白話覆述 → 確認 → 才派工。
3. 修完主對話自己先看截圖（包括使用者指出問題的那個角度）；還有瑕疵就先修或老實說。
4. 這張使用者說 OK，才換下一張。

## 7. 中斷與接手

- 雲端容器會重開或被回收：背景程序中斷，本機檔案可能消失。
- **新 session 看不到舊對話，也聯絡不到舊 agent**。接手步驟見 `SKILL.md` 的「接手工作」。不確定的事先問使用者。
- 依 manifest 記錄的進度**重新派 agent**，從最後完成的那一步接著做；本機檔案不在就從儲存空間或服務的任務 ID 取回。
- 因此：**每完成一步就更新 manifest 並上傳**；程式定期打包備份（不含登入資料）。

## 8. 儲存整理

- 容器硬碟很小、模型檔很大（每個生成候選約 20 MB，每個封閉模型約 70–100 MB）。不要囤中間檔。
- 有每日下載上限的儲存：下載前先估總量，大量讀取的檔案放在沒有下載上限的儲存。
- 封存：用不到的工作檔整批搬到物件儲存（保留原路徑，附索引檔：路徑、大小、md5、狀態），**核對大小與 md5 之後**才刪本機；要用再拿回來。
- 直接刪：否決的實驗、檢查截圖、計算暫存。服務端可用任務 ID 重新下載的原始模型不必另外存（manifest 要記 ID）。
- 祕密：登入檔放在任何 repo 以外，用完刪掉；工具在目前目錄留下的快取資料夾不要被 commit 或上傳。
