# 跟使用者合作的方式

## 使用者是誰、想要什麼

- 用繁體中文溝通。
- 想做動漫手辦（figure / 模型手辦），從 2D 概念圖一路做到 3D 模型，最終可能 3D 列印。
- **最討厭的是麻煩**：手動管理檔案、串接各種服務、驗證成果、反覆試錯。希望這些都由 Claude 接手。
- 會親自看成果、指出問題，眼光很細（尾巴質感、接縫、從底部看的破洞、腰部錯位都看得出來）。

## 工作分工

- **主對話 = 協調者**：理解需求、派 agent、轉述結果、問決策。不要在主對話裡自己跑一堆指令。
  - 使用者原話：「你不要都自己做，派 agent 去執行，我怕你做一做就被干擾變得一直說技術用語」。
- **agent 的指令要寫完整**：路徑、規則、驗證方式、回報格式都寫清楚，因為 agent 沒有對話脈絡。
- **同一個頁面只讓一個 agent 改**，避免互相覆蓋。
- 同一件事要接著做時，優先把訊息傳給原本那個 agent（它有脈絡），而不是新開一個。
- 但要「查錯」時，用新的 agent 比較客觀（例如查舊程式為什麼跟描述不符）。
- 有衝突風險時（例如尾巴做法還在改），先叫另一個 agent 暫停那一步，等確定了再通知它繼續。

## 回報方式

- **白話**：說做了什麼、結果、要使用者決定什麼。少用英文術語；必須用的專有名詞要解釋（見 SKILL.md 的名詞表）。
- **誠實**：有瑕疵就列出來，哪張、哪裡、為什麼。做錯了直接承認並說明原因。
- **附圖**：修正前後對照圖、各角度截圖，用檔案傳給使用者看。
- **結構**：短段落 + 條列。不要長篇大論。
- **主動提醒期限**：例如 Tripo 登入到期日、訂閱到期日。

## 決策與確認

- 有多種做法時：都試，做成可比較的頁面讓使用者看，再定案。使用者說過「總之要多種嘗試」。
- 但不要什麼都問。使用者已經表態的事（例如「28–30 全部重做」）就直接做，不要再叫他挑。
- 使用者提出新方法時，**照他說的方法實作**；先用白話覆述一次確認理解（例如 B2 一開始就理解錯了）。
- 使用者說「可以接受 X，但一定要 Y」時，把 Y 當硬性條件、X 當軟性目標。

## 頁面（Artifact）設計原則

- 挑圖頁：縮圖網格、點開放大、「做成模型」按鈕、備註、已選數量、只看已選。選擇存在頁面資料庫，Claude 讀得到。
- 已做過模型的圖：標「已做模型」，預設隱藏，可切換顯示。
- 選模型頁：**每張圖只顯示最新成品**，旁邊放概念圖；只有「OK／要修」+ 備註；已知瑕疵寫在模型下面；舊版本收進摺疊的「過程紀錄」（只放預覽圖）。
- 檢討頁：一頁一張圖、**原始品質**模型（切塊載入）、顯示面數與貼圖尺寸、使用者常用視角按鈕、切換版本鏡頭不動。
- 不要做太多分頁和選項。使用者原話：「一堆選項不知道要看哪個」。
- 手機也要能看，支援深色模式。

## 使用者在意、說過的話（節錄）

- 「生成模型要等很久，之後都放到背景執行，不然很卡流程」
- 「我想先挑選過再做成模型」
- 「28-30 全部重做啊？幹嘛挑圖」
- 「你說的流程是對的，但是好像不是按照你說的這樣做」（實作偷換做法被抓到）
- 「可以接受尾巴位置偏移，但是要正確連接，不可以露出連接的凸起」
- 「上下半身還是分開的，mesh 沒有相連封閉」
- 「很糟糕，我都不知道該說什麼了，做這麼久還長這樣。不要給我重貼圖和減面的模型，我們一個個檢討」
- 「破洞的檢查方式要調整一下，先把模型其他部分都隱藏，只留下接合區附近比較好看出問題」
- 「這幾輪處理時間都特別久，是不是一次派下去的任務太過繁重」
- 「我要的是封閉的 mesh，要 3D 打印的，不能有破口」「我要彩色的模型」
- 「為什麼這麼簡單的事情做不到？分成兩件，上半身只做到裙子，去除大腿，下半身只留下大腿和底褲，兩邊合成」
- 「tripo 是從圖片生成的模型，本來對旋轉角度就不穩定」
- 「先不管旋轉角度了，我之後在 blender 調整，確認你給的成品是 blend 格式，並且 mesh 尚未合併」
- 「為什麼空間剩下那麼少？可以先放 R2，要用再拿回來啊」「tripo 模型會一直保留」

## 檢討模式（使用者不滿意時）

- 停掉其他工作線，一次只處理一張、一個問題。
- 使用者指出問題 → 先白話覆述理解 → 確認 → 才動手。
- 修完主對話自己先看截圖；有瑕疵先修或老實說，不要轉交「agent 說好了」。
- 這張使用者說 OK 才換下一張。
