# 任務切分、派工與驗收

來自 2026-10-18 對所有 agent 工作紀錄的檢討。這幾天「做很久、品質又一直不過」的原因與改法。

## 檢討出的問題

1. **一次派太多事**：一個 agent 要「修問題 + 套用到 6 或 15 張 + 對照圖 + 重做網頁 + 發布 + 備份」，跑 7–9 小時，檢查被省略。
2. **自己修、自己驗、自己說過關**：多次回報「乾淨」，使用者隔天就找到洞。
3. **驗收指標本身有錯**：
   - 尾巴「接口被遮住 ≥97%」把頭髮和尾巴自己的毛也算進去；只算身體時常只有 48–63%，尾巴其實浮著。
   - 破洞檢查看整隻模型，被裙子／腿／頭髮擋住；模型又是雙面顯示，洞後面看到的是另一片暗色內面，不是背景，自動偵測抓不到。偵測到的可疑像素還被 agent 判成「不是洞」。
   - 修一個地方時只檢查那個地方，沒回頭看整隻 → 修背面時把正面弄破。
4. **給使用者看的不是驗收的那個**：網頁上的模型被減到約 12% 面數、貼圖縮成 2048；「封閉版」又是重建網格、重烘貼圖。
5. **多條線同時改同一批檔案**：程式被複製分叉，後來的修正沒套到另一批；硬碟被塞滿。
6. **用語太技術**，使用者得回頭問名詞。

## 時間花在哪

- 等待（等使用者審查、等別的 agent 的程式）、重複的長時間計算（尾巴定位每張 5–16 分鐘、封閉重建 5 小時以上且被系統砍掉重跑）、反覆調參數、環境問題（機器重開、硬碟只剩 1–3 GB）。
- 對照：只做「一個模型、一個頁面」的任務，12 分鐘就完成。

## 之後的做法

1. **一張圖、一個問題、一個 agent**，目標 30–60 分鐘；每 45 分鐘回報進度附截圖；超時就停下回報，不自己加碼。
2. **修 → 驗 → 發布分開**。修的 agent 交出截圖；主對話自己看過（必要時另派驗收 agent）才給使用者；發布另派小任務。
3. **接合處必做的檢查**：
   - 只留接合區附近，其他部位隱藏。
   - 上半身／下半身／尾巴各用不同顏色。
   - **單面顯示（背面剔除）+ 洋紅背景**；任何洋紅或背面露出 = 缺陷。
   - 從正下方、內側、左右低角度、近距離看；並截「使用者截圖的那個角度」。
   - 檢查尾巴時隱藏頭髮，只算身體有沒有接住。
   - 修完後**整隻模型**再檢查一次（防止修 A 壞 B）。
   - 程式檢查：單一整體、0 開口邊、0 非流形邊、自我穿插只允許在單一零件內部。
4. **你看的就是驗的那個**：一律原始品質。
5. **同一批檔案同時只讓一條線改**；程式不複製分叉。
6. **回報先講「看起來怎樣、哪裡還壞」**，再講數字。
7. **長時間任務注意環境**：雲端機器可能重開；中斷時把訊息傳給原 agent 讓它從中斷處繼續（檔案通常還在）。

## 派工 prompt 要寫清楚的東西

- 只做哪一張、哪一個問題；明確列出「不要做」的事。
- 檔案路徑、可用工具、禁止事項（不刪面、不減面、不重建、不改貼圖、不碰登入檔）。
- 驗收清單（上面第 3 點）與輸出路徑。
- 時間上限與回報字數上限。
