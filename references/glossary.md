# 名詞表

跟使用者說話時用左欄的中文，第一次出現時用右欄的白話解釋。

## 流程與 2D

| 名詞 | 白話解釋 |
|---|---|
| 手辦（figure） | 角色模型公仔。這裡不是指圖表。 |
| 概念圖 | 角色的設計圖，是所有步驟的來源。 |
| 配件（accessory） | 要另外生成再接上去的部位，例如尾巴。 |
| 基準模型（baseline；舊稱「模型 A」） | 原圖直接轉成 3D 的模型。只拿來截背面圖、看大致方向，不能當方向標準。 |
| 去配件正面圖 | 把配件（例如尾巴）從正面圖擦掉、其他不變的圖。 |
| 雙參考重畫背面（舊稱「新 B2」） | 拿「基準模型背面截圖」和「圖像模型畫的背面圖」兩張當參考，讓圖像模型重新畫一張完整的背面圖。不是剪貼。 |
| 直接畫背面（舊稱「B3」） | 只從正面圖讓圖像模型畫背面。品質次於雙參考重畫背面。 |
| 遮罩剪貼背面（舊稱「舊 B2」，已淘汰） | 把頭髮剪下貼到背面截圖上。邊緣對不齊。 |
| 圖像編輯模型 | 能照指示修改圖片的 AI，例如 gpt-image 系列、nano-banana（Google 的圖像模型）。 |

## 生成

| 名詞 | 白話解釋 |
|---|---|
| 圖轉 3D 服務 | 從圖片生成 3D 模型的服務，例如 Tripo。 |
| Direct Texture ×4 | Tripo 的生成方式：一次生成＋三次免費重試 = 4 個候選模型，挑最好的。 |
| 多視角生成（multiview） | 同時給正面＋背面圖生成，背面比較準。 |
| 分開生成 | 上半身、下半身、配件分別生成再接起來；臉和頭髮細節比較好。 |
| 上半身／下半身 | 上半身：頭到腰，保留完整衣服下襬。下半身：腰以下整雙腿（含小腿、鞋）＋底褲／短褲或褲子。 |
| 任務 ID | 服務端每次生成的編號；憑它可以重新下載原始模型。 |

## 3D 模型

| 名詞 | 白話解釋 |
|---|---|
| 網格（mesh）、面、頂點 | 模型由很多小三角形（面）組成，三角形的角是頂點。 |
| 封閉實體（closed solid / watertight） | 沒有任何開口、內外分明、可以 3D 列印的形狀。 |
| 開口邊（boundary edge） | 只屬於一個面的邊 = 破口的邊緣。要是 0。 |
| 非流形邊（non-manifold edge） | 被三個以上的面共用、或結構錯亂的邊。要是 0。 |
| 零體積重複面 | 兩片位置相同、背對背的面，沒有厚度，會造成非流形邊。 |
| 自我穿插 | 模型某處穿進自己裡面。 |
| 貼圖（texture）、貼圖座標（UV） | 貼圖是模型表面的顏色圖片；貼圖座標記錄每個面對應圖片的哪一塊。 |
| 重烘貼圖（re-bake） | 重新產生一張貼圖。會變糊，禁止。 |
| 重建網格（remesh／體素／SDF／泊松） | 把整個模型重新算一次形狀。細節會變軟，禁止。 |
| 減面（decimate） | 減少面數讓檔案變小。品質變差，禁止。 |
| 布林運算（boolean） | 用兩個實體做「相減、合併」。精確布林（exact boolean）結果仍是封閉實體。 |
| 切除體（cutter） | 用來從上半身「減掉」大腿的實心形狀；必須平滑、一整塊。 |
| 放樣（loft） | 沿著一圈輪廓拉出平滑的面，用來補切除體的邊緣。 |
| 剛體旋轉 | 整塊轉動，不縮放、不變形。 |
| 髖部轉軸（hip pivot） | 下半身旋轉的中心點，在兩腿根部中間。 |
| 單面顯示（背面剔除，back-face culling） | 只畫面的正面。破洞會直接透出背景，檢查破洞必用。 |
| 疊層（已淘汰） | 兩半只是疊在一起、靠刪面藏接縫。不能列印。 |

## Blender 與交付

| 名詞 | 白話解釋 |
|---|---|
| 物件（object） | Blender 裡一個獨立的東西，例如 Upper、Lower。 |
| 子物件（parenting） | 把 A 設為 B 的子物件，B 動時 A 跟著動（切除體設為 Lower 的子物件）。 |
| 修改器（modifier）／套用（apply） | 修改器是「還沒真正改模型」的即時效果；套用後才真的寫進模型。 |
| 自訂屬性（custom property） | 存在物件上的備註數值，例如參考角度。 |
| 3MF | 帶顏色的 3D 列印檔格式。STL 只有形狀、沒有顏色。 |

## 工作管理

| 名詞 | 白話解釋 |
|---|---|
| 主對話（協調者） | 跟使用者說話、派工、把關的那個 session。 |
| agent | 主對話派出去做重活的背景工作者；看不到對話內容。 |
| 切塊載入 | 把大模型檔切成小塊放上網頁，瀏覽器再組回原檔；讓使用者看原始品質。 |
| 封存 | 把用不到的檔案搬到雲端物件儲存，附索引，核對後刪本機。 |
| manifest | 每張圖的進度紀錄檔（舊稱「對照清單」）。見下方欄位。 |

## manifest 欄位

每張圖一筆（JSON），每完成一步就更新並上傳：

- `image_key`：圖名／編號（例如 `i1`）與一句描述
- `source`：概念圖路徑
- `picks_note`：挑圖時的備註
- `tasks`：服務任務 ID，依零件與候選分開（baseline、upper、lower、accessory），並標出選用哪個
- `versions`：每個版本（v1、v2…）的檔案路徑（本機與雲端）、做了什麼、驗收結果
- `status`：待挑／生成中／修補中／待驗／待使用者看／OK／否決
- `feedback`：使用者回饋（日期＋轉述）
- `next`：下一步
- `updated_at`
