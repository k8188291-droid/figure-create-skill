# 服務與環境

**不要把任何金鑰、登入檔、Cookie 寫進這個 repo 或任何上傳的檔案。** 使用者曾把金鑰直接貼在對話裡，已建議更換。

## Tripo Studio（圖 → 3D）

- 用使用者自己寫的工具 auto-tripo 操作 Tripo Studio（不是官方 API）。登入靠瀏覽器登入後匯出的登入檔，雲端機器沒辦法自己登入（Studio 網站會擋雲端），要使用者在自己電腦登入後提供登入檔。
- 登入有到期日（例：2026-10-24），比訂閱到期日（例：2026-10-28）早，要提前提醒使用者重新登入。
- 計價（Premium 訂閱時期觀察到的）：Direct Texture ×4 一張圖 50 點，一次生成 + 三次免費重試 = 4 個候選；多視角生成同價；Studio 內建生圖很便宜。
- 速度：一張圖約 20 分鐘（每個候選 3.5–6.5 分鐘），伺服器可同時跑多個工作。
- 多視角（正面 + 背面）生成在 auto-tripo CLI 裡沒有現成指令，要直接呼叫對應的 Studio 端點。
- 另有官方 API（需另外申請金鑰、另外買點數），適合長期無人看管；目前沒用。
- 生成過的模型會留在 Tripo 帳號裡，可以用任務 ID 重新下載。

## 圖像生成／編輯

- OpenAI 相容的圖像 API（generations / edits），雲端環境透過代理自動帶認證。
- 用途：概念圖、去尾巴、尾巴圖、背面圖（新 B2 用多張參考圖）。

## 儲存

- **Backblaze B2**（桶 `holo-figure`）
  - 免費額度：10 GB 儲存；每日下載約 1 GB、下載類請求每日有上限（帳號未綁卡時無法調高）。
  - 使用者在後台設了上限；撞到時錯誤是 `download_cap_exceeded` / `storage_cap_exceeded`，每日 00:00 UTC 重置。
  - **下載前先估量**，大量下載會讓當天所有工作卡住。上傳不受下載額度影響。
  - 用途：對照清單、程式備份、定案成品。
- **Cloudflare R2**（也有一個 `holo-figure` 桶，放了概念圖副本）
  - 下載不收費、沒有每日下載上限 → 需要大量讀取的檔案放這裡。
  - 雲端機器用 Cloudflare 的 `cf` CLI，透過裝置登入（使用者在瀏覽器輸入驗證碼）。
  - CLI 會在當前目錄留快取資料夾，不要讓它被 commit。
- **Tripo 帳號**本身就是模型的永久保存處（使用者確認）：原始模型用任務 ID 重新下載，不必另外存。對照清單一定要記任務 ID。
- **R2 封存**：雲端機器的工作檔整批搬到 R2 `archive/<日期>/`（保留原路徑，附 INDEX.json：路徑、大小、md5、狀態），先核對 R2 上的大小與 md5 才刪本機。之後清理時刪掉 Tripo 原檔（有 ID 的）、否決的實驗、檢查截圖、計算暫存。

## Claude Artifact（給使用者看的網頁）

- 預設私人。可用頁面資料庫存使用者的選擇（挑圖、OK／要修），Claude 讀得到。
- 限制：一個版本 ≤256 MB、≤511 個檔案；一次發布 ≤64 MB、≤255 個檔案。
- `.glb` 不能直接當檔案發布。**給使用者審查一律原始品質**：把 GLB 原封不動切成 ≤11 MB 的區塊（用平台接受的副檔名），前端下載、組回、SHA-256 檢查後載入；多個版本共用的區塊只傳一次，必要時 gzip 傳送再還原。（舊做法：壓成 12–30% 面數、2K 貼圖的 base64 JSON——使用者否決，不要再用來審查。）
- 檔案太多時，把縮圖拼成每輪一張大圖。
- 更新同一個頁面要用同一個原始檔路徑，不然會開出新連結。

## 雲端執行環境

- 機器會重開或在閒置後被回收；背景程序會中斷，本機檔案不保證保存。
- 硬碟大約 40 GB 可用，很容易被模型檔塞滿；剩不到 3 GB 就該整批封存到 R2。
- Blender 可在雲端機器上以無頭模式執行（建 .blend、評估修改器、算圖預覽）。
- 精確布林與修補：manifold3d（可帶貼圖座標通過布林）、trimesh；不要用會整個重建的修補工具。
- 原則：每完成一步就把小型對照清單上傳雲端；程式定期打包備份（不含任何登入資料）。
- 使用者說過「不要用這個 repo」→ 手辦工作在 repo 以外的獨立資料夾進行。
